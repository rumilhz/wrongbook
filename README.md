# WrongBook · Agent 前置防错错题本

> 把「出错 → 诊断 → 修复」的浪费，变成「动笔之前就知道不能怎么写」的规则库。

AI Agent 天生具备纠错能力——报错后它能自己分析、自己修复。但纠错是要付代价的：额外的诊断时间、分析精力、来回的 token。真人学习时，老师提前告诉你"不能这么写"，你就少走很多弯路。**这个仓库就是给 Agent 装一个"老师"**：在它动手写命令、写代码、装包之前，先把规则送到它面前。

---

## 一、为什么需要它

大多数 Agent 的"经验机制"是**事后型**的：

```
命令报错 → 诊断根因 → 查找/回忆方案 → 修复 → （可选）记录
```

这条链路每一步都花钱，而且**同一类错误会在不同的会话里反复出现**——因为"记录"和"下次避免"之间没有可靠的桥梁。

本方案的目标是**前置型**：

```
写命令之前 → 核对禁则清单 → 命中即换写法 → 不报错
```

核心逻辑很简单：Agent 本来就解得开错，只是要花更多时间；**如果它在写之前就知道不能这么写，整个纠错环节就根本不发生。**

## 二、核心理念（四个设计决策）

### 1. 记录格式：禁则式，不是复盘式

```markdown
- [bash] 禁止直接 ls 可能不存在的路径 —— 因为 exit 2 会让整条命令判 failed；写法 `[ -d p ] && ls p`
```

- **「禁止 X」** = 预防性写法，是主体
- **「因为会 Y」** = 一行根因，用来判断"换个写法的同类场景"是否也适用
- 「如何解决」**默认省略**，只在解决过程有非显然的坑（重启/清缓存/握手命令）时才追加备注

为什么不写复盘？"为什么出错"和"如何解决"是过程性内容，对未来价值递减；**唯一可复用的是预防性写法**。禁则式一条一行、可扫描、省 token。

### 2. 触发机制：常驻指令 > 被动检索

这是本方案最关键的洞察：

| 机制 | 工作原理 | 能否保证"写之前"触发 |
|---|---|---|
| 长期记忆 / lessons 数据库 | 索引常驻，正文**按需检索**（语义/关键词命中才加载） | ❌ 不行——"写之前"这个时刻**没有报错关键词可搜**，检索不会触发 |
| 常驻指令文件（AGENTS.md / CLAUDE.md / REASONIX.md） | **每个相关 turn 必在上下文**（cache-stable prompt 前缀） | ✅ 行——规则每轮都在，写之前天然可见 |

**结论：要实现"源头防错"，必须有一条常驻指令**，它的职责是元规则——"写命令前先核对错题本"。记忆负责"查得到什么"，指令负责"每次动手前提醒你查"。

### 3. 双层隔离：指令文件只放元规则，禁则全进记忆

业界反面教训（Claude Code 社区多次报告）：**200 行规则全被忽略**。原因是指令文件每轮全量加载：
- token 成本随行数线性上涨
- 规则太多会稀释优先级，Agent 反而"看不见"

所以：
- **常驻指令文件**：只放 1 条元规则 + ≤5 条最高频铁律（保持 <30 行）
- **记忆/错题本**：放完整禁则清单，按需检索
- 新增禁则**只进记忆**，永远不写进常驻文件

### 4. 渐进沉淀 + 定期修剪

- 沉淀时机有三种：自己报错后 / 用户直接纠正时（不等犯错）/ 用户提供的他处案例
- 同类错误第二次出现 → **扩充那一条**（加示例/变体/备注），不新建、不重写
- 定期合并重复条目、删除过时条目，防止清单膨胀失效

## 三、快速开始（3 步，约 3 分钟）

### Step 1：创建常驻指令文件

在你的 Agent 工作区放一个 `AGENTS.md`（Claude Code 用 `CLAUDE.md`，Reasonix 用 `REASONIX.md`），内容直接抄 `templates/AGENTS.md`（其中「高频铁律」的 `（示例）` 条目是占位，替换成你自己最常踩的坑）：

```markdown
## 元规则：写之前先查错题本（防错优先，不做事后纠错）
- 每次执行 bash/PowerShell 命令、写代码、安装包**之前**，先检索错题本（lessons.md / 记忆），
  核对当前操作是否命中禁则；命中即用预防性写法，**不等报错再纠错**。
- 命令失败 / exit code 非 0 / 工具报错后：按「禁止 X —— 因为会 Y」格式沉淀或扩充错题本，不写长复盘。

## 高频铁律（最痛的 ≤5 条，错题本速览）
- （示例）禁止在 bash 双引号内嵌含 `$_` 的 `powershell -Command "..."` —— 会损坏命令。
- （示例）禁止直接 `ls`/操作可能不存在的路径 —— exit 2 判 failed；先 `[ -d p ] &&` 判断。
```

### Step 2：创建错题本

复制 `templates/lessons.seed.md`（**种子库**：作者真实沉淀的 9 条禁则，标注了适用范围）为 `lessons.md`，删掉你不用的领域；纯空模板在 `templates/lessons.md`。有长期记忆系统的平台可直接存进记忆（见 `docs/implementation.md` 平台适配）。

### Step 3：遇到第一个错误，沉淀第一条

命令报错后，按这个格式追加：

```markdown
- [bash/PowerShell] 禁止在 bash 双引号内嵌含 `$_` 的 `powershell -Command "..."`
  —— 因为 `$_` 会被 bash 当变量展开吞掉 → 命令损坏 exit 1；
  改写成 `.ps1` 脚本执行，或整串用单引号包裹让 bash 零展开
```

从第二条开始，同类问题出现时**编辑已有条目**，而不是新增。

## 四、使用规则速查

| 场景 | 动作 |
|---|---|
| 准备写命令/代码/装包 | **先核对**错题本相关条目，命中即换写法 |
| 命令报错 / exit code 非 0 | **沉淀**为「禁止 X —— 因为会 Y」禁则 |
| 用户直接纠正我 | **沉淀**（不等犯错） |
| 同类错误第二次出现 | **扩充**那一条（加示例/变体），不新建 |
| 清单膨胀 / 有过时条目 | **修剪**：合并重复、删除不再适用的 |

## 五、已验证的真实案例（本方案运行实录）

| 领域 | 禁则 | 教训来源 |
|---|---|---|
| bash | 禁止直接 `ls` 可能不存在的路径 → exit 2 判 failed（`2>/dev/null` 也救不了退出码） | 实际运行：探测不存在的目录 |
| bash/Windows | 禁止把 MSYS 路径（`/tmp`）直接传给 Windows 程序 → **报成功但实际没写文件** | 实际运行：officecli 批量生成 |
| bash | 禁止用未加引号定界符的 heredoc 写含 `\n`/`$` 的内容 → 内容被 shell 展开变形 | 实际运行：JSON 生成 |
| bash/PowerShell | 禁止在 bash 双引号内嵌含 `$_` 的 PowerShell 命令 → `$_` 被吞、命令损坏 | 实际运行：注册表查询 |
| 浏览器自动化 | 禁止连续操作间隔 >2-3 秒 → daemon 会清空闲 session | 实际运行：BrowserAct |

这些案例说明：**禁则不需要多，每一条都来自一次真实的 token 浪费**，沉淀后就不会再犯第二次。

> ⚠️ **关于「验证」的诚实声明**：上表是**一次性叙事**，不构成量化证据。本仓库自 **2026-08-06** 起按 `docs/validation.md` 协议记录三类事件（HIT 命中 / INCIDENT 报错 / RULE 沉淀），4 周后回填首份量化报告（命中率、避错数、复发率、估算节省 token）；数据日志见 `data/validation-log.md`。

## 六、与其他方案对比（完整版见 `docs/comparison.md`）

| 方案 | 触发时机 | 前置防错 | 存储 | 评价 |
|---|---|---|---|---|
| **本方案**（WrongBook） | 常驻指令 + 按需检索 | ✅ | 指令文件 + 记忆/lessons.md | 轻量、零依赖、平台无关 |
| Claude Code 的 CLAUDE.md rules | 常驻 | ✅ | 单一指令文件 | 方向一致，但规则与指令混存、易膨胀失效 |
| lessons 数据库类 skill（如 self-improvement-loop） | 被动检索 | ❌ | 外部 DB | 事后型，检索不到"写之前" |
| graphify 等 lessons 聚合器 | 会话后聚合 | ❌ | 生成的 LESSONS.md | 事后报告，无前置 |
| mem0 / MemGPT / Letta 记忆框架 | 语义检索 | ❌ | 向量库 | 是记忆基础设施，不是防错规则；重 |
