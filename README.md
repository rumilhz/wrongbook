# WrongBook · Agent 前置防错错题本

[English](README.en.md) | [中文](README.md)

> 把「出错 → 诊断 → 修复」的浪费，变成「动笔之前就知道不能怎么写」的规则库。

AI Agent 天生会纠错——报错后它能自己分析、自己修复。但纠错是有代价的：诊断时间、分析精力、来回的 token。真人学习时，老师提前告诉你"不能这么写"，你就少走很多弯路。**这个仓库就是给 Agent 装一个"老师"**：在它动手写命令、写代码、装包之前，先把规则送到它面前。

---

## 为什么需要它

大多数 Agent 的"经验机制"是**事后型**的：

```
命令报错 → 诊断根因 → 查找/回忆方案 → 修复 → （可选）记录
```

每一步都花钱，而且同类错误会在不同会话里反复出现——"记录"和"下次避免"之间没有可靠的桥梁。

本方案是**前置型**的：

```
写命令之前 → 核对禁则清单 → 命中即换写法 → 不报错
```

核心逻辑：Agent 本来就解得开错，只是要多花时间；**如果它在写之前就知道不能这么写，整个纠错环节就根本不发生。**

## 快速开始（3 步，约 3 分钟）

**Step 1：创建常驻指令文件**

在工作区放一个 `AGENTS.md`（Claude Code 用 `CLAUDE.md`，Reasonix 用 `REASONIX.md`），内容直接抄 `templates/AGENTS.md`（「高频铁律」的 `（示例）` 条目是占位，换成你自己最常踩的坑）：

```markdown
## 元规则：写之前先查错题本（防错优先，不做事后纠错）
- 每次执行 bash/PowerShell 命令、写代码、安装包**之前**，先检索错题本，
  核对当前操作是否命中禁则；命中即用预防性写法，**不等报错再纠错**。
- 命令失败 / exit code 非 0 / 工具报错后：按「禁止 X —— 因为会 Y」格式沉淀或扩充错题本。
```

**Step 2：创建错题本**

复制 `templates/lessons.seed.md`（种子库：真实沉淀的 9 条禁则，标注了适用范围）为 `lessons.md`，删掉你不用的领域；纯空模板在 `templates/lessons.md`。

**Step 3：遇到第一个错误，沉淀第一条**

命令报错后，按此格式追加（同类问题第二次出现时**编辑已有条目**，不新增）：

```markdown
- [bash/PowerShell] 禁止在 bash 双引号内嵌含 `$_` 的 `powershell -Command "..."`
  —— 因为 `$_` 会被 bash 当变量展开吞掉 → 命令损坏 exit 1；
  改写成 `.ps1` 脚本执行，或整串用单引号包裹让 bash 零展开
```

## 使用规则速查

| 场景 | 动作 |
|---|---|
| 准备写命令/代码/装包 | **先核对**错题本相关条目，命中即换写法 |
| 命令报错 / exit code 非 0 | **沉淀**为「禁止 X —— 因为会 Y」禁则 |
| 用户直接纠正 | **沉淀**（不等犯错） |
| 同类错误第二次出现 | **扩充**那一条（加示例/变体），不新建 |
| 清单膨胀 / 有过时条目 | **修剪**：合并重复、删除不再适用的 |

---

## 四个设计决策（摘要）

1. **禁则式记录**：`禁止 X —— 因为会 Y`，一条一行、可扫描、省 token；"如何解决"默认丢弃，只保留可复用的预防性写法 + 一行根因
2. **常驻指令 > 被动检索**：记忆检索在"写之前"没有关键词可搜，必须靠每轮常驻的元规则触发——这是本方案区别于所有 lessons/记忆类方案的根本点
3. **双层隔离**：指令文件只放元规则 + ≤5 条铁律（防膨胀失效），完整禁则进记忆按需检索
4. **渐进沉淀 + 修剪**：沉淀时机有三种；同类合并单条；定期修剪防清单腐烂

完整论证见 [docs/principle.md](docs/principle.md)。

## 真实案例（本方案运行实录）

| 领域 | 禁则 | 来源 |
|---|---|---|
| bash | 禁止直接 `ls` 可能不存在的路径 → exit 2 判 failed | 实际运行：探测目录 |
| bash/Windows | 禁止把 MSYS 路径（`/tmp`）直接传给 Windows 程序 → 报成功但没写文件 | 实际运行：批量生成 |
| bash/PowerShell | 禁止在 bash 双引号内嵌含 `$_` 的命令 → 命令被吞损坏 | 实际运行：注册表查询 |
| 浏览器自动化 | 禁止连续操作间隔 >2-3 秒 → daemon 清空闲 session | 实际运行：BrowserAct |

> ⚠️ **关于「验证」的诚实声明**：上表是**一次性叙事**，不构成量化证据。本仓库自 **2026-08-06** 起按 [docs/validation.md](docs/validation.md) 协议记录三类事件（HIT 命中 / INCIDENT 报错 / RULE 沉淀），4 周后回填首份量化报告（命中率、避错数、复发率、估算节省 token）；数据日志见 [data/validation-log.md](data/validation-log.md)。

## 与其他方案对比（完整版见 [docs/comparison.md](docs/comparison.md)）

| 方案 | 触发时机 | 前置防错 | 存储 | 评价 |
|---|---|---|---|---|
| **本方案**（WrongBook） | 常驻指令 + 按需检索 | ✅ | 指令文件 + 记忆/lessons.md | 零依赖、平台无关、纯指令驱动 |
| Claude Code 的 CLAUDE.md rules | 常驻 | ✅ | 单一指令文件 | 思路相近；规则与指令同文件，需注意控制体积 |
| lessons 数据库类 skill | 被动检索 | 部分 | 外部 DB | 适合团队级知识库；需运行维护 |
| graphify 等 lessons 聚合器 | 会话后聚合 | 部分 | 生成的 LESSONS.md | 适合项目复盘场景 |
| mem0 / MemGPT / Letta | 语义检索 | 部分 | 向量库 | 记忆基础设施，定位不同；适合大规模记忆需求 |
