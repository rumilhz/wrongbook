# 验证方法：如何量化「前置防错」的效果

> 本方案的价值主张是"用每轮几十 token 的常驻成本，换掉每类错误无限次重犯的事后成本"。
> 这句话能不能成立，必须由**数据**说了算——这也是本仓库与"个人心得"类项目的分水岭。
> 本文件定义记录协议与指标；记录从 **2026-08-06** 开始（见 `data/validation-log.md`），
> 满 4 周后回填首份报告。

---

## 1. 三个核心指标

| 指标 | 定义 | 计算方法 |
|---|---|---|
| **命中率 Hit Rate** | 元规则触发检索的次数中，命中有用禁则并因此改变写法的比例 | `HIT / 检索次数(Preflight)` —— 检索次数必须由**事件流记录**（非事后补录），否则不统计 |
| **避错数 Prevented** | 因命中禁则而**没有发生**的报错次数 | 每次 HIT 记 1（⚠️ **反事实问题**：HIT ≠ 真避错——原写法可能本来就不会错。仅作**行为指标**，不作效果 claim） |
| **复发数 Regressions** | 已在错题本中的禁则，同类错误**再次发生**的次数 | 每次 INCIDENT 且命中已有禁则记 1 |

**衍生指标**：
- **复发率**：`复发数 / exposure 次数`（exposure = 该禁则实际被应用到同类场景的次数）——**必须记录 exposure 才能算真实复发率**；未记录时**只能报 observed regressions 绝对数**，禁止用 `复发/(避错+复发)`（该式把 HIT 与复发两种不同 exposure 混同，是 40% 虚高的根源）。
- **估算节省 token**：`避错数 × 单次纠错平均成本`（经验系数 3）——同上，受反事实影响，仅作参考不作证明。

## 1.5 数据集分层（v0.1 数据治理）

为保证效果 claim 不被污染，所有事件/规则按来源分层，**只有 A 层可作效果验证**：

| 层 | 定义 | 可用于 |
|---|---|---|
| **A · instrumented** | 事件流逐条记录、可归因、有 exposure | 效果验证（复发率/命中率） |
| **B · historical** | 带日期/场景归因的历史沉淀，但未逐条关联事件 | 知识库 |
| **C · external** | 用户/他处提供的案例 | 候选规则 |
| **D · unattributed** | 批量补录、无逐日归因 | 仅知识库，**禁止用于效果 claim** |

> 2026-08-06 ~ 09-02 周期数据：规则大多带实测日期（归 B 层），但未逐条关联 RULE 事件且无 exposure 记录，严谨计为 **D 层**——**本周期无法给出任何真实效果率**。

## 2. 记录协议：三类事件

### HIT（命中，前置生效）

```
- [2026-08-06] HIT  领域=bash 禁则=「禁止直接 ls 不存在路径」 效果=改用 `[ -d p ] &&` 写法 避错=1
```

记什么：日期、命中的禁则、实际换成的写法、是否确认避免了报错。

### INCIDENT（报错，无论是否命中）

```
- [2026-08-06] INCIDENT 命令=... 根因=... 命中已有禁则=是/否
  沉淀=新增/扩充/不沉淀（不沉淀的原因：一次性噪音/环境问题）
```

记什么：任何 exit code 非 0 或工具报错。重点标记：**是否命中已有禁则**——
命中 = 复发（机制失效，需查原因）；未命中 = 新坑（沉淀后未来可避）。

### RULE（沉淀）

```
- [2026-08-06] RULE 新增/扩充 条目=「禁止 X —— 因为会 Y」
```

记什么：错题本的每次增删改，与 revision 对应。

## 3. 数据来源

| 来源 | 用途 |
|---|---|
| 会话历史（Agent 平台自动保存） | 回溯 INCIDENT 与 HIT，核查 Agent 是否真的执行了元规则 |
| 错题本修订记录（revision） | RULE 事件：条目增长曲线 |
| 用户反馈 | 用户纠正 = 最高质量的沉淀信号（前置，非报错） |

## 4. 月度报告模板

```markdown
## 2026-09 验证报告（周期：08-06 ~ 09-05）

- 错题本条目：9 → N（+M，其中新增 K / 扩充 L / 修剪 P）
- 检索触发次数：T 次（元规则执行情况）
- 命中：H 次（命中率 H/T）
- 避错：P 次（估算节省 ≈ P × 单次纠错成本）
- 复发：R 次（复发率 R/(P+R)）——若 >0，列出复发条目及原因
- 结论：本周期验证了什么 / 机制哪里失效 / 下一步
```
