# A/B 对照实验协议（WrongBook 效果验证）

> 状态：**协议定义（2026-09-02），待数据满足后执行**。
> 目的：回答唯一有价值的问题——**"记住错误能否让 Agent 少犯已知错误？"**
> 前置：核心 12 条已六要素化（Trigger/Forbidden/Verification），核对率由 `scripts/wrongbook-audit.py` 外部审计。

## 1. 为什么必须做（诚实前提）

- 本周期（08-06 ~ 09-02）数据计 Dataset D，**无法证明任何效果**（README 已诚实声明）。

## 2. 实验设计

**样本**：N = 30 个陷阱任务，从核心/参考规则中挑 **可构造陷阱** 的最高价值规则（目标 ≥10 条高频规则，每条 ≥2 任务）。

**两组**（同一 Agent / 同一环境 / 随机化顺序，避免记忆污染）：

| | Control | Treatment |
|---|---|---|
| 无 WrongBook | 有 WrongBook（全文 + rule-index + 核对仪式） |
| 陷阱任务随机序 | 同批任务随机序 |
| 不注入规则 | 正常触发核对 |

**任务构造原则**：每条规则对应一个"不遵守 → 高概率触发已知错误"的任务。
例：规则「禁止 bash 双引号内嵌含 `$_` 的 powershell」→ 任务"用一条命令查询当前用户目录下的文件数"（若按 `$_` 写法必崩）。

## 3. 指标（四维，缺一不可）

| 指标 | 定义 | 意义 |
|---|---|---|
| **Regression Rate** | 陷阱任务中犯已知错的次数 / 陷阱任务数 | 核心效果 |
| **Task Success** | 任务成功完成率 | 防过度保守（规则多了不敢做） |
| **Overhead** | tool calls / token / 耗时 / 人工介入次数 | 规则系统成本 |
| **False Positive** | 规则误判场景（本不会错却因规则不敢做） | 规则副作用 |

**判定标准**（设想）：Regression 显著下降（如 60%→25%）**且** Task Success 不降、Overhead 可接受 → WrongBook 获得"有效"资格；否则结论为"记录有价值但防错未生效"。

## 4. 记录格式（每任务一行 CSV）

```csv
task_id,rule_id,group,outcome(prevented|incident|fp|none),tool_calls,tokens,notes
```
